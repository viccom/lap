# F3 · 多图叙事（多图 + 模板 → 云端讲故事）技术方案与实施计划

> 状态：草案 v1（2026-11-11）· 分支 `develop` · **硬前置：F1 全部完成**（模板/客户端/证据/标注基建直接复用，本方案不重复设计）。

## 1. 目标与非目标

**目标**
- 用户多选照片（网格多选 / 集合托盘 / 集合）→ 选一个模板 → 发送给云端 VL，一次请求多图，返回一篇叙事文本。
- 产物可编辑（用户改写后保存用户版，与 AI 原版并存）；可从叙事跳回任一张图。
- 图片顺序可拖拽调整（叙事的时序语义）。
- 沿用 F1 全部宪法：人工触发、证据落库（vl_calls 复用）、AI 产物不碰用户字段。

**非目标**
- 不做自动批量叙事；不做视频；不做叙事导出排版（打印/蒙太奇已有上游功能可组合）。

## 2. 对 lap 代码的修改点清单（唯一权威清单）

### 2.1 gateway 侧（唯一需要扩展外部服务的点）

vl-gateway 新增端点（gateway 是自有服务，改动独立于 lap 仓库，另行提交）：

```
POST /vl/story
  {"images_b64": [..N 张按序..], "prompt": ..., "model": optional}
  → 同 /vl/analyze 形状（content/model/request_id/usage）
```
- 契约与单图端点完全一致，仅 images 为数组——lap 侧客户端用同一个响应解析器。
- 数量上限 gateway 侧配置（建议默认 ≤12 张，防止 payload 失控；512 缩略图单张 ~50-150KB，12 张 ≈ 1.8MB b64 后 ~2.4MB，reqwest 默认无压力）。

## 3. 数据模型（迁移 v25）

```sql
CREATE TABLE vl_stories (
  id INTEGER PRIMARY KEY,
  file_ids TEXT NOT NULL,            -- JSON 数组，顺序即叙事顺序
  template_id INTEGER NOT NULL,
  template_version INTEGER NOT NULL,
  model TEXT,
  ai_text TEXT NOT NULL,             -- AI 原文（不可变）
  user_text TEXT,                    -- 用户编辑版（可空=未编辑）
  title TEXT,                        -- 用户可改
  call_id INTEGER NOT NULL REFERENCES vl_calls(id),
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```
- 复用 `vl_calls`（F1 建的证据表）：story 调用也留完整 prompt/raw/usage，file_ids 记在 request 侧——若需从证据反查，prompt_actual 里天然含图片占位说明。
- 不加 file 级 FK 级联：叙事是跨文件产物，图删了叙事仍在（text 引用无害，UI 对缺失 file_id 显示「已删除」占位）——避免上游 afiles 删除路径被我们的外键拖住。

## 5. 与上游同步的兼容性预算

- 全部新文件 + 3 个低风险锚点（router 数组/Content 菜单/main.rs 列表），rebase 冲突预期极小。

# F1 · 图片理解（云端 VL）技术方案与实施计划

> 状态：草案 v1（2026-11-11）· 分支 `develop` · 目标：为单张照片调用局域网 vl-gateway 的视觉模型，按可选的不可变提示词模板生成理解结果，本地持久化，带完整溯源。

## 1. 目标与非目标

**目标**
- 人工触发（按钮/菜单），单张或批量排队；绝不自动跑。
- 提示词模板：内置默认模板（只读）+ 用户自定义模板；模板**不可变版本化**——一次调用锁定一个模板版本，改模板不改变历史标注的语义。
- 产物 = 结构化标注（caption/tags/scene 等字段由模板声明）+ 原始返回文本，存本地 SQLite。
- 每次调用留证据：实际 prompt、raw 响应、模型名、request_id、token 用量。
- 幂等：同一 (file_id, template_version) 成功过即不重复调用，除非用户显式「重新理解」。

**非目标**
- 不自动批量理解全库（无额度系统，触发即用户意愿）；不修改 afiles 任何用户字段（rating/comments/tags）；不做 OCR。

## 3. 数据模型（迁移 v23）

```sql
-- 模板：不可变版本化，name+version 唯一
CREATE TABLE vl_templates (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  version INTEGER NOT NULL DEFAULT 1,
  prompt_template TEXT NOT NULL,        -- 占位符 {file_name} {exif_summary}
  response_spec TEXT NOT NULL,          -- JSON：声明期望字段（caption/tags/scene…）与中译
  is_builtin INTEGER NOT NULL DEFAULT 0,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL,
  UNIQUE(name, version)
);
-- 标注：一次成功调用一行；AI 产物与用户数据完全隔离（不碰 afiles）
CREATE TABLE vl_annotations (
  id INTEGER PRIMARY KEY,
  file_id INTEGER NOT NULL REFERENCES afiles(id) ON DELETE CASCADE,
  template_id INTEGER NOT NULL,
  template_version INTEGER NOT NULL,
  model TEXT NOT NULL,
  result_json TEXT NOT NULL,            -- 按 response_spec 解析
  raw_text TEXT NOT NULL,
  call_id INTEGER NOT NULL REFERENCES vl_calls(id),
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_vl_ann_file ON vl_annotations(file_id);
-- 调用证据：无论成败都留
CREATE TABLE vl_calls (
  id INTEGER PRIMARY KEY,
  file_id INTEGER NOT NULL,
  template_id INTEGER NOT NULL, template_version INTEGER NOT NULL,
  prompt_actual TEXT NOT NULL,          -- 渲染后的最终 prompt
  raw_response TEXT,                    -- 失败时 NULL
  model TEXT, request_id TEXT,
  prompt_tokens INTEGER, completion_tokens INTEGER,
  status TEXT NOT NULL,                 -- ok | error | cancelled
  error TEXT,
  duration_ms INTEGER, created_at INTEGER NOT NULL
);
```

幂等判定：`vl_annotations` 上加 `UNIQUE(file_id, template_id, template_version)` 的**部分索引**（仅 status=ok 的 annotation）——SQL 层防重复烧钱。删除文件时标注级联删除（跟随 lap 的 FK CASCADE 风格）。

## 4. vl-gateway 契约（复用 homepix 的现有服务，不改 gateway）

```
POST /vl/analyze
  {"image_b64": ..., "prompt": ..., "model": optional}
  → {"content": ..., "model": ..., "request_id": ..., "usage": {"prompt_tokens":..,"completion_tokens":..}}
```
- lap 侧只做 HTTP 客户端（reqwest 已在依赖，rustls）。URL 从环境变量 `LAP_VL_GATEWAY_URL` 读，缺失 → 功能禁用（UI 显示「未配置」），**不影响应用其他部分**。
- 图片输入用 512 缩略图（athumbs.thumb_data，与 AI 嵌入同源），无缩略图回退原图但先过 `is_cloud_only` 检查（t_utils.rs:483-500）——**云文件绝不读原图上传**。

## 6. 与上游同步的兼容性预算

- 每次 `git rebase main` 预期冲突点：FileInfo.vue、Settings.vue（各 ~2 行改动，易解）；t_migration.rs 若上游也加了 v23 → **重编号我们的迁移为 v23+N**（迁移号让位上游，表名唯一所以数据无损）。
- main.rs 的 handler 列表冲突：纯追加行，git 自动合并概率高。

# F1 · 图片理解（云端 VL）技术方案与实施计划

> 状态：草案 v2（2026-11-11，契约按 magpie 实测重写）· 分支 `develop` · 目标：为单张照片调用局域网 magpie 网关的视觉模型（Anthropic 协议），按可选的不可变提示词模板生成理解结果，本地持久化，带完整溯源。

## 1. 目标与非目标

**目标**
- 人工触发（按钮/菜单），单张或批量排队；绝不自动跑。
- 提示词模板：内置默认模板（不可删除；编辑后保存为用户自己的副本，内置行不变）+ 用户自定义模板；模板**不可变版本化**——一次调用锁定一个模板版本，改模板不改变历史标注的语义。
- 产物 = 结构化标注（caption/tags/scene 等字段由模板声明）+ 原始返回文本，存本地 SQLite。
- 每次调用留证据：实际 prompt、raw 响应、模型名、request_id、token 用量。
- 幂等：同一 (file_id, template_version) 成功过即不重复调用，除非用户显式「重新理解」。

**非目标**
- 不自动批量理解全库（无额度系统，触发即用户意愿）；不修改 afiles 任何用户字段（rating/comments/tags）；不做 OCR。

## 3. 数据模型（迁移 v23）

```sql
-- 模板：不可变版本化，name+version 唯一
CREATE TABLE vl_templates (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  version INTEGER NOT NULL DEFAULT 1,
  prompt_template TEXT NOT NULL,        -- 占位符 {file_name} {exif_summary}
  response_spec TEXT NOT NULL,          -- JSON：声明期望字段（caption/tags/scene…）与中译
  is_builtin INTEGER NOT NULL DEFAULT 0,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL,
  UNIQUE(name, version)
);
-- 标注：一次成功调用一行；AI 产物与用户数据完全隔离（不碰 afiles）
CREATE TABLE vl_annotations (
  id INTEGER PRIMARY KEY,
  file_id INTEGER NOT NULL REFERENCES afiles(id) ON DELETE CASCADE,
  template_id INTEGER NOT NULL,
  template_version INTEGER NOT NULL,
  model TEXT NOT NULL,
  result_json TEXT NOT NULL,            -- 按 response_spec 解析
  raw_text TEXT NOT NULL,
  call_id INTEGER NOT NULL REFERENCES vl_calls(id),
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_vl_ann_file ON vl_annotations(file_id);
-- 调用证据：无论成败都留
CREATE TABLE vl_calls (
  id INTEGER PRIMARY KEY,
  file_id INTEGER NOT NULL,
  template_id INTEGER NOT NULL, template_version INTEGER NOT NULL,
  prompt_actual TEXT NOT NULL,          -- 渲染后的最终指令
  system_actual TEXT,                   -- 渲染后的模板正文（可为 NULL）
  raw_response TEXT,                    -- 失败时 NULL
  thinking_text TEXT,                   -- 模型 reasoning 原文（可空）
  model TEXT,                           -- 网关回显的实际模型
  request_id TEXT,                      -- 网关台账主键 msg_...
  input_tokens INTEGER, output_tokens INTEGER,
  cache_read_tokens INTEGER, thinking_tokens INTEGER,
  stop_reason TEXT,
  status TEXT NOT NULL,                 -- ok | error | cancelled
  error TEXT,
  duration_ms INTEGER, created_at INTEGER NOT NULL
);
```

幂等判定：`vl_annotations` **只存成功结果**（失败只进 `vl_calls`），表级 `UNIQUE(file_id, template_id, template_version)` —— 同一照片同一模板版本不会重复烧钱。"重新理解"= 先删该唯一键的旧标注行再插入（历史调用证据仍完整保留在 `vl_calls`）。删除文件时标注级联删除（跟随 lap 的 FK CASCADE 风格）。

## 4. magpie 网关契约（2026-11-11 实测核对，非照文档想象）

网关：`http://192.168.199.8:3425`，协议 = **Anthropic Messages**（`/v1/messages`），与 homepix 用的 vlgw 门面**不是**同一套协议，本方案按实测重写。

### 4.1 请求

```
POST {base_url}/v1/messages
Headers: x-api-key: <key>
         anthropic-version: 2023-06-01
         content-type: application/json
Body: {
  "model": "auto/deepseek-v4.1-flash",      // 可选；默认 auto/deepseek-v4.1-flash
  "max_tokens": 1500,                        // 必须给足：reasoning 模型的 thinking 也吃这个额度
  "system": "可选的模板正文（实测被接受）",
  "messages": [{"role":"user","content":[
      {"type":"image","source":{"type":"base64","media_type":"image/jpeg","data":"<裸 base64>"}},
      {"type":"text","text":"本次请求的指令"}
  ]}]
}
```
- 图像是**裸 base64**，不带 `data:` 前缀；`media_type` 按真实格式（jpeg/png/webp）。
- **一条消息可放多张 image 块**（实测两图 OK）——F3 多图叙事因此**不需要新端点**，复用同端点即可。
- 可用视觉模型（实测 `auto/` 前缀形式）：`auto/deepseek-v4.1-flash`、`auto/glm-5.3-flash`、`auto/hy4free`、`auto/minimax-m3.1-flash`。

### 4.2 响应（成功）

```json
{"content":[{"type":"thinking","thinking":"..."},{"type":"text","text":"```json\n{...}\n```"}],
 "id":"msg_...","model":"group/auto-deepseek-v4-1-flash","role":"assistant",
 "stop_reason":"end_turn","type":"message",
 "usage":{"input_tokens":71,"output_tokens":205,"cache_read_input_tokens":384,
          "output_tokens_details":{"thinking_tokens":144}}}
```
实测要点（直接决定客户端实现）：
1. **`content` 是数组，可能先出现 `thinking` 块**——不能假设 `content[0]` 是文本；必须**按 type 过滤并拼接所有 `text` 块**。
2. `text` 里是 **```json 围栏包裹的 JSON**——解析前必须剥离围栏；剥离失败则整段当原文保存（不丢内容）。
3. `model` 回显的是**实际服务的模型**（请求 `auto/deepseek-v4.1-flash` → 回显 `group/auto-deepseek-v4-1-flash`），**溯源要记回显值**，不是请求值。
4. `usage` 用 Anthropic 命名（input_tokens / output_tokens / cache_read_input_tokens / thinking_tokens）。
5. `stop_reason` 可能为 `max_tokens`（thinking 吃光额度、没产出正文）——此时正文为空，要能识别并给出可读原因。

### 4.3 错误

| 情形 | HTTP | 响应体 |
|---|---|---|
| key 无效 | 401 | `{"error":{"code":null,"message":"...","param":null,"type":"authentication_error"}}` |
| 模型不存在 | 404 | `{"error":{"message":"magpie knows no model ..."}}`（OpenAI 风格 error 包裹） |

错误体是 OpenAI 风格 `{"error":{code,message,type}}`，与 Anthropic 风格的 `{"type":"error","error":{type,message}}` 不同——客户端按实测解析，兼容两种。

### 4.4 配置与密钥（不入库）

- `LAP_VL_GATEWAY_URL` / `LAP_VL_API_KEY` 环境变量优先；缺失时可在设置页填写，**存后端 app-config.json**（本地明文，仅本机）。
- **key 永不出现在任何响应里**：设置页只读回 `configured: bool`，不回传原文；日志与错误信息只写"未配置/鉴权失败"，**不写 key 本身**。
- key 不进仓库、不进提交信息、不进 `docs/`（本方案正文只出现 key 的**变量名**，不出现值）。
- 图片输入用 512 缩略图（`athumbs.thumb_data`，与 AI 嵌入同源）；无缩略图回退原图，但先过 `is_cloud_only` 检查（t_utils.rs:483-500）——**云文件绝不读原图上传**。
- 超时按 homepix 经验给足（上游可能 30–40s 才回首字节），默认 180s。

### 4.6 真实验收结果（2026-11-11，对真实家庭照片）

**A. 客户端直连探针**（`cargo test -- --ignored real_gateway_probe`，用原图）：

```

request_id  = msg_84eb2106e9264db68260c0d0d3be1f4c
stop_reason = end_turn
usage       = input 1076 / output 167 / thinking 123   ← thinking 块正确分离到独立字段
duration_ms = 95297
text        = {"caption":"一个穿着蓝色棉衣的小孩躺在草地上，旁边停着一辆橙色滑板车，车把上挂着一片黄叶。",
               "tags":["小孩","滑板车","草地"]}
```

**B. 完整生产链路**（`cargo test -- --ignored real_library_e2e`，从真实库取文件）：

```
迁移链自动跑完 v18 → v23（"Applying migration 23: Image understanding templates…"）
file_id = 1, template = 内置描述 v1
outcome = Annotated { call_id: 1 }
result_json = {"caption":"一个小男孩站在葡萄园里，右手举着一串刚采摘的青葡萄，左手拿着红色剪刀…",
               "tags":["小男孩","葡萄园","青葡萄","采摘","剪刀","田园","户外","童趣","丰收","果园"]}
evidence: model=group/auto-deepseek-v4-1-flash  request_id=msg_1b5e21e4…  usage 319/302  5.3s  status=ok
```

三条由此得出的硬事实：

1. **缩略图 vs 原图差 18 倍**：原图 95 秒 / 缓存缩略图 5.3 秒（vision token 少一个量级）。**「优先缩略图」不只是省流量，是省 18 倍时间**——这条决定了 F3 多图必须走缩略图。
2. **单次调用预算**：缩略图路径 5–10 秒，原图路径 95 秒。180 秒超时对缩略图绰绰有余，对原图只剩 53% 余量。
3. **模型有时直接输出裸 JSON，有时带 ```json 围栏**——围栏剥离必须容错（剥离失败保留原文、标 `_unparsed`），两种形态都不能丢内容。

### 4.7 模板的 system 与 prompt 分开（实现修正）

首版实现只有 `prompt_template`（落 user 消息），`system_actual` 恒为 NULL。实测把「只输出 JSON」放进 **system** 更稳（网关接受 system 顶层参数）。因此模板表增加 `system_template` 列：

- `vl_templates.system_template TEXT NOT NULL DEFAULT ''`（随迁移 v23 一起，尚未发布可直接改 v23 定义）
- `create_vl_template` / `update_vl_template` / `list_vl_templates` 均带该字段；渲染与 prompt 用**同一套占位符**
- 渲染结果分别落 `prompt_actual` 与 `system_actual`
- 「只输出 JSON、字段形如…」这类格式约束放 system；「描述这张照片」这类任务指令放 prompt

## 7. 占位符扩展（2026-11-12）

模板的 prompt 与 system 共用同一套占位符，缺失值渲染为空串，未知占位符原样保留。全部字段只读，不触碰库内数据。

| 类别 | 占位符 | 来源 |
|---|---|---|
| 身份/拍摄 | `{file_name}` `{taken_at}` `{camera}` `{exif_summary}` | 文件名、taken_date、e_make+e_model、镜头/快门/光圈/ISO |
| 库内关系 | `{tags}` `{people}` | afile_tags→atags 名称、faces→persons 名称（逗号连接，按名称排序） |
| 位置 | `{location}` `{gps}` | geo_name/admin1/admin2/cc；经纬度（6 位小数，仅在两者都有值时） |
| 描述性元数据 | `{comments}` `{title}` `{headline}` `{description}` `{artist}` `{copyright}` `{software}` | 对应 afiles 列 |
| 相机细节 | `{camera_make}` `{camera_model}` `{lens}` `{exposure}` `{f_number}` `{focal_length}` `{iso}` `{flash}` | e_* 列 |
| 文件属性 | `{dimensions}` `{duration}` `{rating}` `{favorite}` `{format}` `{file_size}` `{created_at}` `{modified_at}` | 宽×高、时长 M:SS/H:MM:SS、评分、收藏、格式标签、人类可读大小、时间戳 |

实现点：`PromptContext`（`t_vl.rs`）、`render_template` 替换表、`prompt_context`（纯 AFile 字段）与 `prompt_context_with_conn`（补 tags/people）；`LibrarySource::prompt_context` 走后者。模板管理页的 `vl.placeholders_hint` 已列出全部 31 个占位符。隐私提示：`{gps}`/`{location}` 会把拍摄地点随请求发往云端网关，不需要地理位置的模板不要引用。

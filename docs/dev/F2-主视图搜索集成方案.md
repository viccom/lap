# F2 主视图搜索集成方案（图片理解搜索进入主界面）

日期：2026-11-13
状态：**设计稿，待拍板**（拍板项见 §8）
前置：F2-搜索扩展技术方案（实验台隔离验证已全绿）、SEARCH-RESEARCH §4.6（描述文本向量已落地）

## 1. 背景与目标

精确搜索（BM25 FTS5）与语义搜索（描述文本向量）已在实验台（VlLab）完成隔离验证：zh R@1 0.936 / **0.945**、7ms / 10ms、阈值 0.45 列表干净。当前这些能力**只有实验台一个入口**，主视图的统一搜索仍是「上游 LIKE 词面 + CLIP 图像向量（zh R@1 仅 0.255）」，且三档切换 UI 已被摘除（`searchMode` 恒为 `all`）。

目标：把两条已验证的检索通道接入主视图统一搜索，让日常搜索直接受益；语义腿从 CLIP 换为描述向量；保持「新功能先隔离验证、再进主界面」的既定节奏与上游同步预算。

## 2. 现状盘点（代码事实）

> 2026-11-13 补充：以下 CLIP 职责、文件唯一性、官方搜索页机制的完整核实见 **[ARCHITECTURE-FACTS-2026-11-13.md](./ARCHITECTURE-FACTS-2026-11-13.md)**。关键结论：官方界面**永远跑 `all` 档**（`searchMode` 无 setter 无 UI，FTS 腿与 vector 单档从未被执行）；`all` 档词面路只覆盖 **7 列**（name/comments/e_title/e_headline/e_artist/e_copyright/e_software，**不含 tags/people/图片描述**），向量腿是英文 CLIP（zh R@1 0.255）。

## 3. 设计决策

### D1 三档模型与语义腿换血（核心）

> **[2026-11-13 用户拍板更新：本节方案已被合并裁决取代]** 最终形态 = 「新独立侧栏入口」方案（见 [UX-图片理解与搜索改进方案.md](./UX-图片理解与搜索改进方案.md) §1）：**官方 `getUnifiedSearchFileList` 与其 CLIP 腿完全不动**（官方 all 档行为保留，本方案的语义腿换血不再作用于官方管线），精确/语义两档只存在于新入口 `SIDEBAR.AI_SEARCH` 的 `getAiSearchFileList`。附带收益：**Content 对拍断言基线无需变更**。本节保留原设计供参照；其中仍适用的部分：语义腿实现细节（`searchSemanticMatches`）、组标签分数、空态两文案、`SearchModePicker.vue`（落在新面板内）。

| 档位 | planSearch | 执行路径 | 定位 |
|---|---|---|---|
| 全部 all（默认，不变） | lexical + vector | LIKE 词面（文件名/元数据）+ **语义腿：`search_captions`（描述向量）** | 兼容上游习惯的日常档 |
| 精确 precise | fts | `search_fts`（BM25，name/people/meta/tags/caption×5） | 全字段全文、部分命中按相关度排序 |
| 语义 semantic | vector | `search_captions` + 阈值 0.45 | 同义/改写查询，列表干净 |

- **语义腿替换**：`getUnifiedSearchFileList` 中 vector 腿从 `searchSimilarImages(currentImageSearchParams)` 换为新的 `searchSemanticMatches(searchText, limit)`（见 §4）。理由：CLIP 对中文文本查询 R@1 0.255 且无阈值语义（全库噪音），描述向量 0.945 + 0.45 阈值同时给「找到」与「干净」。
- **CLIP 不退役**：`search_similar_images` 继续服务以图搜图与 subjects 智能相册（`QUERY_KIND.IMAGE_SEARCH`，Content.vue:6918/8006 的图像路径不动）。仅**文本搜索**的语义腿换血。
- `imageSearchLanguageUnsupported` 检查（默认模型 + 非拉丁文本）只属于 CLIP 文本塔，文本语义腿不再需要，随替换移除该分支对文本搜索的影响。
- 单档模式复用同一管线（plan 开关已有）：precise 单组、semantic 单组，组标签分别复用现有键。

### D2 档位选择器（UI）

- **新组件 `SearchModePicker.vue`**：三段式选择（segmented）+ 当前档一句话提示（如语义档提示「按图片描述的语义相似度匹配，只显示高置信结果」）。
- **放置**：`ImageSearch.vue` 搜索输入框下方（侧栏面板内，搜索相关 UI 聚在一起）。`ImageSearch.vue` 只加锚点式引入（约 3 行 diff），选择器本体全部在新文件。
- 持久化：`configStore.setSearchMode(mode)`（新增 setter，模式同 `setImageSearchModel`），全局生效。

### D3 语义结果呈现（Phase 1 克制）

- **组标签带分数区间**：`语义命中 12 · 相似度 0.78–0.46`（复用 `semantic_matches` 键 + 追加分数字段）。
- **Phase 1 不动缩略图**：GridView/Thumbnail 保持零 diff，不做每图分数角标（放 Phase 2，见 §7）。
- 合并顺序维持上游形状：text → semantic → precise（`all` 档 fts 关闭，实际两组）；去重按现有 `knownIds` 逻辑。

### D4 过滤与空态

- 语义腿与现有 visual 腿同待遇：`passesAlbumFilters` + `favoritesOnly` 客户端过滤；`search_captions` 无 fileType 参数，type 过滤在 `getFilesByIds` 结果上客户端做（与 lexical 路径的 fileType 参数等义）。
- **语义档空结果且库内有已理解图片** → 空态提示「没有语义匹配（已理解 N 张图片）」；**captions=0** → 提示「还没有已理解的图片，去图片理解实验台批量标注」（N 来自 `embed_status`，搜索面板挂载时取一次）。
- 语义腿失败（本地模型缺失/云端不可达）：与现有 visual 失败同策略——catch → 空组，不拖垮其他腿；连续失败时组标签位置显示降级提示。

### D5 重排不进主视图（Phase 1）

主视图路径保持零网络、零 LLM 等待（用户指令：重排只是兜底）。实验台保留重排勾选作为高级面。Phase 2 若需要，以「结果标题行可选按钮」形态补（§7）。

## 5. 交互细节

1. 侧栏 SEARCH 面板：输入框 → 档位选择器（三段，默认「全部」）→ 历史列表；选择器切换立即对下一次搜索生效（当前结果不自动重跑，避免打字中途抖动；切换时若已有 searchText，提示可按 Enter 重搜——Phase 1 简化为切换即重跑当前查询，与历史点击行为一致，见 §8 拍板项 4）。
2. 搜索执行：三档共用 `getUnifiedSearchFileList`，`planSearch` 决定开哪几路（已存在）。
3. 结果分组：`all` = 词面命中 + 语义命中（各带条数）；`precise` = 单组「精确命中 · N/M 命中列: …」（现有逻辑）；`semantic` = 单组「语义命中 N · 相似度 a–b」。
4. 语义分数仅展示两位小数，区间 = 组内最高–最低。
5. 语义空态文案区分「已理解 N 张但没有匹配」与「尚未理解任何图片」。

## 9. 风险

- 对拍断言基线变更若上游同期改动搜索区，rebase 时需人工合并——收敛在 Content.vue 单文件内，可控。
- `search_captions` 在主视图成为高频路径：本地 bge 10ms/查询无压力；云端源用户若选 cloud，多 ~200ms 网络往返（设置里已有源切换，语义组标签可带来源标识，Phase 1 不做）。
- 无标注照片在语义/精确档不可见（caption 缺失）——预期管理靠空态提示与 Phase 2 覆盖徽标；根治靠批量 VL 标注（既定方向，未排期）。

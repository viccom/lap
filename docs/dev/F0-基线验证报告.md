**踩坑与解法**（已写入 `AGENTS.md` 与机器档案）：
1. **cargo 经代理必须关 multiplexing**：`CARGO_HTTP_MULTIPLEXING=false CARGO_HTTP_VERSION=HTTP/1.1`。症状是进程持有连接、CPU≈0、crate 缓存不增长、日志停在某行不动——第一次 fetch 卡了 10 分钟无进展。
2. `cargo tauri dev` **必须从项目根启动**：`beforeDevCommand` 是 `pnpm --dir ../src-vite dev`，在 `src-tauri/` 内启动会路径失配。
3. CARGO_HOME 是 `C:\ProgramData\scoop\persist\rustup\.cargo`（scoop 版 rustup），**不是** `~/.cargo`——查缓存路径别找错。

## 3. 失败归因（全部为上游 v0.3.3 既有缺陷，非本机环境问题）

### 3.1 Rust：4 个失败 — 均为 Windows 平台语义差异

| 测试 | 断言 | 根因 |
|---|---|---|
| `t_storage::migration_tests::copy_failure_keeps_source_and_cleanup_failure_is_reported` | `checkpoint_db(...).is_err()` | 测试用「把文件当目录」构造元数据错误；Windows 返回 NotFound（被当作"缺失"而非"错误"），POSIX 返回 ENOTDIR |
| `metadata::xmp::import_tests::new_scan_rebuilds_index_without_directory_timestamp` | `find_xmp_sidecar(&image).is_none()` | 依赖目录 mtime 粒度与大小写敏感语义 |
| `metadata::files::tests::transfer_batch_detects_new_source_and_destination_sidecars` | `"Destination XMP already exists"` | sidecar 存在性判定在 Windows 的大小写不敏感文件系统上不同 |
| `metadata::files::tests::transfer_batch_detects_new_owner_between_commands` | NotFound | 同上 |

**依据**：上游 CI（`.github/workflows/`）**从不执行 `cargo test`**（Windows job 只构建+打包），故这些失败从未被上游发现。

### 3.2 前端：8 个失败文件 — 两种成因

| 成因 | 文件 | 说明 |
|---|---|---|
| TypeScript 6 的 `ts.transpile` 默认输出 **ESM**（保留 import），而测试用 `new Function(code)` 执行 → `SyntaxError: Cannot use import statement outside a module` | afAreaPersistence / albumRecovery / cloudFileRefresh / offlineCatalog / xmpWriteback | 显式传 `module: ts.ModuleKind.CommonJS` 即可修复；上游 CI 同样不跑这些测试 |
| 源码重构后**测试锚点失配**（测试用字符串 `indexOf` 从 Content.vue slice 源码） | fileInfoMetadata / filterSelection / shortcutsLayout | 例：源码里 `:empty="hasConfirmedEmptyContent"` 在，测试期待的 `<div v-else-if="empty"` 已不存在 |

**依据**：Node 20 与 Node 26 下**同样复现**；lock 锁定 TypeScript 6.0.2 与 CI 一致 → 与本机环境无关。

## 4. 对 F1–F3 的约束（已写入 AGENTS.md）

1. **新前端测试不得使用 `new Function(ts.transpile(...))` 模式**（TS 6 下失效）。两种正确写法：①把被测逻辑抽成 `.mjs`/`.js` 模块直接 import；②用 `startup.test.mjs` 的 `vm.SourceTextModule` 模式（需 `--experimental-vm-modules`）。
2. **Rust 测试要避开平台语义依赖**：不要用「文件当目录」「大小写敏感」「目录 mtime 粒度」构造场景，否则 Windows 上必红（上游 4 个失败即此类）。
3. 门禁基线：改动前后对比 **323 passed / 4 failed(平台特有)** 与 **29/37 前端文件**，新增失败即为本次引入。

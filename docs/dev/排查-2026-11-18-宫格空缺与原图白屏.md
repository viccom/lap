# 排查记录：宫格空缺 / 原图打不开（2026-11-18）

> 症状、取证、根因与修复的完整台账。**最终根因**：前端引用了未注册的快捷键动作
> `file.moveToFolder`，Thumbnail / MediaViewer 的 render 抛异常，Vue 把组件根节点替换成
> 空注释 `<!---->`，于是格子空白、查看器整块不可见。
> 用户环境：`D:\LapPortable\lappp.exe`（debug 构建），库「董开源家」2,773 项（167 CR2，
> `D:\Users\viccom\Pictures\董开源备份`），数据目录 `%LOCALAPPDATA%\com.julyx10.lap.debug`。

## 症状

1. 宫格中间出现空缺，滚动后空缺位置随之变化；有时整屏空白；
2. 双击缩略图查看原图：主区完全不可见（不是加载慢，是查看器根本没渲染出来）；
3. 重建索引无效；改一次宫格大小（滑杆）能短暂恢复部分格子。

## 根因（实锤）

`src-vite/src/common/fileMenu.ts` 的「移动到文件夹…」菜单项保留了
`shortcut: shortcut('file.moveToFolder')`，但动作注册表 `common/shortcuts.ts` 里**没有**
`file.moveToFolder`（上游 8a882112 已把动作定义与注册一并删除，fork 的菜单引用残留）。

`useFileMenuItems` 返回 `computed`，Thumbnail / MediaViewer 在 render 中读取它构建右键菜单，
于是 **每次渲染都走 `getShortcut('file.moveToFolder')` 并抛错**。Vue 的
`renderComponentRoot` 捕获 render 异常后会把组件根节点替换为 Comment（`<!-- -->`），
所以：

- 宫格 cell 里 Thumbnail 整块消失 → 空缺；
- MediaViewer 根节点同样被替换 → 双击后「原图完全不可见」（查看器其实已打开，只是渲染成空注释）；
- 改宫格大小会让 Thumbnail 重新渲染，但新渲染同样抛错——只有菜单数据未变的旧实例会短暂保留。

## 为什么之前的结论错了

`47524672` 的判断（后台重建与 UI 共享 4 许可池导致饥饿）**不是本 bug 的根因**。许可池
拆分本身是合理的独立改进，保留；但宫格空缺/查看器白屏由上面的前端异常直接造成，与缩略图
生成许可无关。沙盒对照实例当时「渲染正常」，不能作为许可池结论的证据。

## 修复

- `src-vite/src/common/fileMenu.ts`：删除「移动到文件夹…」项上悬空的
  `shortcut: shortcut('file.moveToFolder')`（与上游 8a882112 对齐；该项本就没有默认键位）。
- `src-vite/src/common/shortcuts.ts`：`getShortcutLabels` 对未知动作 id 返回 `[]` 而不是抛错。
  这是**显示路径**（菜单在 render 中构建），必须全函数化；未知 id 最多导致“没有快捷键提示”，
  不能炸掉整棵渲染树。派发路径 `getShortcut` / `matchesActionShortcut` 保持抛错语义。
- `src-vite/tests/shortcutsLayout.test.mjs`：新增两条回归测试——
  1) label 查询对未知 id 不抛错并返回空；2) `fileMenu.ts` 中出现的每个 `shortcut('…')`
  动作都必须在注册表中存在。
- 部署：`build/windows/` 三件套由 `scripts/build-windows.ps1` 产出；`lappp.exe` 与
  `lappp-client.exe` 内嵌前端已更新（新 bundle hash 在、旧 hash 与 `moveToFolder` 均消失），
  `D:\LapPortable` 覆盖前已按时间戳备份旧文件。`lappp-server.exe` 不内嵌前端（运行时读
  `--web-dir` / `resources/web`），本次无需更新。
- 构建脚本自 2026-11-18 起默认 `-BuildProfile release`（出到 `build/windows/`），
  `-BuildProfile debug` 出到 `build/windows/debug/`；`D:\LapPortable` 当时部署的是
  debug 版（便携测试形态，数据目录 `com.julyx10.lap.debug`）。
